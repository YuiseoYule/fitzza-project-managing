# Fitzza WBS Dashboard

GitHub의 `data/tasks/*.json`을 단일 원본으로 사용하는 읽기 전용 간트 대시보드입니다.

## Local development

```bash
npm install
npm run validate:data
npm run dev
```

## 가중치와 상태

작업 데이터는 `구현과업_계층형_행구조_퍼센트_클라우드추가.xlsx`의 **기능별 구현 task** 시트에 있는 세부 작업 292개와 계획·분석설계의 단일 작업 2개, 총 294개입니다.
`weight`는 D열 **전체 기여도** 또는 단일 작업으로 등록한 영역의 P열 비중을 나타내는 소수 값입니다. 예: `0.01` = `1%`. 기존 1/2 점수 가중치 대신 엑셀의 계층별 배분 결과를 적용합니다.
`effortScore`에는 B열 원본 점수(1~4)를, `source`에는 시트·행·영역·상위 분류·기능 ID를 보존합니다. 상위 합계 행은 별도 작업으로 저장하거나 중복 합산하지 않습니다.
기존 268개 작업의 ID·담당자·상태·일정·선행 관계는 유지했습니다. 엑셀의 작업명·분류는 갱신했으며, 이름/범위가 바뀐 기존 작업의 상태를 새로 검증한 것은 아닙니다. 변경 전 작업명은 해당 비고에 남겼습니다.
엑셀의 FE 알림 영역에 있는 서버 과업도 원본 분류와 가중치를 따르되, 기존 담당자는 유지합니다.
추가된 개발 작업 4개와 클라우드 작업 20개에는 일정을 추정하지 않고 `schedulePending: true`를 지정했습니다. 클라우드 담당자는 원본의 `나연`입니다.
계획(`PHASE-PLAN`, 15%, O6:P6)과 분석설계(`PHASE-ANALYSIS-DESIGN`, 10%, O7:P7)는 사용자 요청대로 각각 하나의 작업으로 등록했습니다. 두 작업은 사용자 확인에 따라 **완료**이며, 담당자와 실제 날짜는 미정입니다. 영역 계획 비중과 작업 가중치를 중복 합산하지 않습니다. 추후 세부 작업으로 분할할 때는 이 단일 작업을 대체해야 합니다.

```json
{
  "weight": 0.002083333333333333,
  "effortScore": 2,
  "status": "완료"
}
```

- 상태: `시작 전`, `진행 전`, `진행 중`, `차단됨`, `완료`, `보류`. 원본의 `진행 전`은 화면에서 `시작 전`으로 표시합니다.
- 가중 진척률 = 완료 작업의 가중치 합 / 보류를 제외한 전체 작업의 가중치 합.
- `완료` 작업은 자신의 가중치 전체를 분자에 반영합니다. 다른 상태의 부분 진행률은 반영하지 않습니다.
- `보류` 작업은 분자와 분모 모두에서 제외합니다. 표와 Excel에는 남고 진행률은 `제외`, 행의 작업 정보 전체(구분·WBS·작업명·유형·산출물·수행인력·기간·가중치·상태·진행률)는 취소선으로 표시됩니다. 상세 화면의 작업명에도 취소선을 표시하며, 오른쪽 날짜 칸의 근무일 색상은 유지합니다.
- `차단됨`은 `보류`와 다르며 계산 대상 가중치에 포함됩니다.
- 모든 작업이 보류이거나 표시된 작업이 없으면 `계산 대상 없음`으로 표시합니다.
- 작업별 진행률은 완료 시 100%, 미완료 시 0%입니다. 기존 `progress` 필드는 하위 호환을 위해 허용하지만 계산에는 쓰지 않습니다. 새 JSON에는 작성할 필요가 없습니다.
- 이전 영문 상태 `not_started`, `in_progress`, `blocked`, `completed`도 지원합니다. `on_hold`는 `보류`와 동일합니다.

예: 완료(가중치 2%), 진행 중(가중치 1%), 보류(가중치 2%)라면 진척률은 2 / 3 = 66.7%입니다.

### 전체 총합 및 원본의 미배분 가중치

화면의 **전체 프로젝트 가중치 총합**은 담당자 필터와 무관하게 전체 작업을 집계합니다. 계획 비중·등록 가중치·완료 가중치·보류 가중치·등록 작업 진척률을 구분합니다.
계획 비중은 원본 `O4:P10`을 옮긴 `data/project-weights.json`에서 관리합니다. 계획 15%, 분석설계 10%, FE 25%, BE 30%, Cloud 10%, 테스트 5%, 배포운영 5%로 합계 100%입니다.

2026-10-07 반영 시점의 원본 검산 결과:

- 원본 상위 합계 `F2`는 FE 25% + BE 30% + Cloud 10% = 65%입니다.
- 실제 최하위 D열 합계는 **62.6623376623%**입니다. FE 25%, BE 27.6623376623%, Cloud 10%입니다.
- BE 알림 영역 `D338`은 4.0909090909%이나, 그 아래 실제 작업 `D340:D344`는 1.7532467532%입니다. 차이 **2.3376623377%p**를 다른 작업에 임의 배분하지 않았습니다.
- 계획 15%·분석설계 10%를 각각 단일 작업으로 추가한 등록 가중치 총합은 **87.6623376623%**입니다. 테스트·배포운영 10%는 아직 작업이 없습니다. 원본의 미배분 2.3376623377%p와 합쳐 12.3376623377%p가 미등록·미배분입니다. 이는 보류 가중치와 별개입니다.
- 등록 작업 진척률은 등록된 작업 범위의 완료/비보류 가중치 비율이며, 전체 프로젝트의 미등록 영역까지 완료됐다는 뜻이 아닙니다.
- 계산에는 원본 소수 정밀도를 사용하고 화면은 소수점 3자리 퍼센트로 표시합니다.

## 원본의 미배정·날짜 미상

- `responsible: ""`는 실제 담당자 미배정입니다. 유형(FE/BE)을 보고 임의로 배정하지 않으며, **미배정** 필터로 조회할 수 있습니다.
- 지정된 담당자 이름 `경민`, `주희`, `지현`, `수혁`, `승원`, `준우`, `나연`도 역할과 함께 지원하며, 이름별 필터로 조회할 수 있습니다.
- 완료 이력이나 보류 업무의 `startDate: ""`, `endDate: ""`는 **날짜 미정**으로 표시합니다. 날짜를 추정하지 않으며 간트 작업 바는 그리지 않습니다.
- 빈 날짜는 두 날짜가 모두 비어 있는 완료/보류 업무 또는 `schedulePending: true`인 업무에만 허용합니다. 날짜를 계획할 때는 두 날짜를 입력하고 `schedulePending`을 제거하거나 false로 바꿉니다. 한쪽만 비어 있거나 미정 표시와 날짜가 동시에 있는 데이터는 거절합니다. 실제 날짜, 선후행 순서, 존재하지 않는 참조, 순환 의존성 검증은 유지합니다.
- 날짜 미상 작업과 연결된 의존성의 날짜 순서는 확인할 수 없으므로 검증 시 안내합니다.
- `progress: null`도 원본 호환용으로 보존하지만 진척률 계산에는 쓰지 않습니다.

## 2026년 10월 근무 달력

`data/work-calendar.json`에서 날짜별 업무 가능량을 관리합니다.

- 근무일: 7·8일, 12~17일, 20~24일, 27~30일.
- 17·24일은 **0.5**: 각 작업 오른쪽 날짜 칸을 회색으로 표시합니다.
- 나머지 근무일은 **1**: 작업 기간에 해당하면 기존 상태 색상을 표시합니다.
- `진행 전`/`시작 전` 작업 기간은 **연한 빨강**으로 표시하여 반일 근무일의 회색과 구분합니다. 화면 범례·상태 표시와 Excel에도 같은 색상을 사용합니다.
- 10월의 그 외 날짜는 **0**: 검은색으로 표시합니다.
- 비근무일·0.5 근무일 색상은 상태 색상보다 우선하며 날짜가 없는 작업에도 표시합니다.
- 10월 밖은 근무 일정 **미설정**으로 취급합니다. 날짜에 마우스를 올리면 가능량을 확인할 수 있습니다.
- 가능량은 달력 표시용이며 작업 가중치나 진척률을 변경하지 않습니다.
- Excel도 같은 달력을 쓰며 6행에 날짜별 가능량, 조건부 서식에 검정·회색 우선순위 및 보류 취소선을 포함합니다.

## Excel 내보내기

화면의 **Excel 내보내기 (.xlsx)** 버튼으로 현재 표시된 작업을 다운로드합니다.
역할 필터, 작업 순서, 날짜 범위, 상태, 가중치, 주차/일자 헤더와 간트 색상을 반영합니다.
전체 결과를 받으려면 **전체 표시**를 누른 뒤 내보내세요. 화면의 가중 진척률도 동일한 표시 범위로 계산합니다.

Excel에는 진척률 수식, 0% 초과 100% 이하 가중치 입력 제한, 상태 선택 목록, 날짜에 따른 간트 조건부 서식과 틀 고정이 포함됩니다.
**가중치 총합** 시트는 내보낸 작업을 영역별 SUMIFS로 집계합니다. 원본 계획 비중과 등록/완료/보류/계산 대상 가중치를 구분하고, 작업 시트의 가중치·상태를 바꾸면 총합도 다시 계산합니다. 필터 내보내기에서는 해당 작업 범위만 집계하므로 전체 총합이 필요하면 전체 표시 후 내보내세요.
파일에서 상태·가중치·기존 날짜 범위 내 일정을 바꾸면 Excel이 수식과 서식을 다시 계산합니다.
날짜 열은 내보내기 시점의 일정 범위이므로 그 밖의 일정으로 바꾸려면 원본 JSON 수정 후 다시 내보내세요.
Excel 수정은 GitHub 데이터로 동기화되지 않습니다. 서버나 토큰 없이 브라우저에서 파일을 생성합니다.

## Dependency CSV import

`predecessorId,successorId` 헤더를 포함한 CSV를 표준 입력 또는 파일 인수로 전달합니다. 이 명령은 후행 작업의 `predecessorIds`에 항목을 추가합니다.

```bash
npm run import:dependencies -- dependencies.csv
# 또는
Get-Content dependencies.csv | npm run import:dependencies
```

수정 후에는 반드시 `npm run validate:data`를 실행하세요. PR과 `main` 푸시에서 같은 검증이 실행되며, `main`에 반영되면 Pages 배포가 시작됩니다. 저장소 설정의 **Pages > Build and deployment > Source**를 **GitHub Actions**로 한 번 지정해야 합니다.
